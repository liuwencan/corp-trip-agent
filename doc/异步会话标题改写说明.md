# 异步会话标题改写说明

## 功能位置

标题改写由 `cn.lwccxy.trip.business.chat.ChatAgentPipeline#asyncUpdateConversationTitle` 执行，在 `ensureConversation` 创建新会话后异步启动。已有会话直接返回，不会重复调用标题模型。

新会话创建时先用用户问题的前几个字符生成默认标题并完成持久化，再将用户原始问题交给模型改写。模型任务运行期间不会阻塞会话创建后的主对话流程。

## 为什么使用 Java 虚拟线程

标题生成的主要等待时间来自远程模型 API 的网络请求，属于阻塞式 I/O 等待。若使用平台线程执行并等待模型响应，线程会在等待期间持续占用操作系统线程资源。

项目运行于 Java 21，使用 `Thread.ofVirtual()` 为这类短生命周期、以 I/O 等待为主的任务创建虚拟线程。这样可以保留直观的同步调用代码，同时降低并发标题任务对平台线程的占用。标题生成是后台辅助工作，失败时只记录日志，不影响 Agent 的主对话流程。

## 模型选择

标题改写使用 Spring Bean `lightWeightModel`，当前模型名为 `qwen3.8-flash`，通过 `@Qualifier("lightWeightModel")` 明确注入到 `ChatAgentPipeline`。

选择 Flash 轻量级模型是因为标题改写只需从首条问题中提炼简短、清晰的中文主题，不需要复杂推理或长文本生成。相较于面向主对话推理的强模型，轻量模型更适合这类短任务，有利于控制调用耗时和成本。生成提示要求仅返回标题文本，避免附带解释或格式内容。

模型 Bean 的定义位于 `cn.lwccxy.trip.agent.config.CorpTripModelConfig#lightWeightModel`。模型名、端点和生成参数以该配置及 `asyncUpdateConversationTitle` 调用时传入的生成选项为准。

## 生成与回写规则

1. `ensureConversation` 发现会话不存在并创建成功后，使用新会话 ID 启动虚拟线程；已有会话不触发标题生成。
2. 虚拟线程调用 `lightWeightModel`，从返回内容中提取文本并去除首尾空白。
3. 空标题不回写；标题超过数据库字段长度时按 Unicode 码点截断，避免截断代理项。
4. 回写 SQL 同时检查会话 ID、用户 ID 和创建时的默认标题。若用户已经手动修改标题，或会话不再属于该用户，模型结果不会覆盖现有数据。
5. 模型调用或回写异常只记日志，不向主对话流程传播。

## 耗时记录

目前测得标题改写平均耗时约 **1918ms**。这是当前环境下的实测值，后续可根据更多样本更新。

方法内使用 `System.nanoTime()` 统计单次任务耗时。计时从虚拟线程开始运行时开始，在模型响应解析和标题长度处理完成后结束，发生在数据库条件回写之前；因此该值不包含数据库回写耗时，也不代表所有机器、网络和模型负载下的固定延迟。日志中的单次耗时可用于持续观察，平均耗时应基于一组成功请求样本计算并记录样本数量与测试环境。
