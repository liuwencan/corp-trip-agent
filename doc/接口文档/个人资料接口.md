# 个人资料接口

接口根路径为 `/user/profile`，同时支持 `/api/user/profile`。均需使用登录接口返回的令牌请求头；响应沿用 `Response`：`success`、`message`、`errorCode`、`data`。

## 接口列表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/user/profile` | 查询本人账户公开信息与个人档案 |
| POST | `/user/profile` | 首次创建本人档案，可同时保存昵称、头像 |
| PUT | `/user/profile` | 局部更新本人资料 |
| DELETE | `/user/profile` | 清除本人档案、昵称和头像，保留账户和密码；重复调用成功 |
| GET | `/user/profile/options` | 查询枚举下拉选项和可编辑字段 |

GET、POST、PUT 的 `data` 结构相同：

```json
{
  "account": {
    "id": 1213,
    "username": "zhangsan",
    "role": "USER",
    "mustChangePassword": false,
    "nickName": "张三",
    "avatar": "https://example.com/avatar.png",
    "createTime": "2026-11-19T10:00:00",
    "updateTime": "2026-11-19T10:00:00"
  },
  "profileExists": true,
  "profile": {
    "baseCity": "南京",
    "level": "P6",
    "namePinyin": "ZHANG SAN",
    "email": "zhangsan@example.com",
    "chineseName": "张三",
    "idType": 1,
    "idNumber": null,
    "phone": null,
    "gender": "M"
  }
}
```

未建立档案时 GET 仍成功，`profileExists=false`、`profile=null`，账户信息正常返回。前端据此选择 POST 或 PUT。只填写昵称或头像也会创建一条档案，其他档案字段保持空值。查询会返回本人已保存的完整证件号码、手机号，前端编辑页面应按需展示，不写入日志或埋点。

## 可编辑字段

全部字段均为选填；每次保存至少提交一个非空值字段或一个清空字段。

| 字段 | 类型与限制 | 保存位置 |
| --- | --- | --- |
| nickName | 非空白字符串，最多 20 字符 | t_user.nick_name |
| avatar | HTTP/HTTPS 地址，最多 255 字符 | t_user.avatar |
| baseCity | 非空白字符串，最多 128 字符 | user_profile.base_city |
| level | 枚举字符串：P5、P6、P7、P8，区分大小写 | user_profile.level |
| namePinyin | 字母组成的姓与名，以空格分隔，最多 128 字符；保存为大写并合并连续空格 | user_profile.name_pinyin |
| email | 合法邮箱，最多 128 字符 | user_profile.email |
| chineseName | 非空白字符串，最多 64 字符 | user_profile.chinese_name |
| idType | 枚举整数：0–9；不接受字符串、浮点数 | user_profile.id_type |
| idNumber | 非空白字符串，最多 64 字符；兼容各类证件，不统一按身份证格式限制 | user_profile.id_number |
| phone | 7–32 字符，至少一个数字，可含 +、空格、括号和连字符 | user_profile.phone |
| gender | 枚举字符串：M（男）、F（女），区分大小写 | user_profile.gender |
| clearFields | 需要清空的字段名数组，字段名限定为上面 11 项 | 对应字段保存为 SQL NULL |

昵称、头像之外的账户字段为只读。`id`、`userId`、`username`、`role`、`passwordHash`、`mustChangePassword`、`credentialVersion`、时间字段及其他未知属性均拒绝写入。修改密码继续使用现有 `PUT /auth/password`。

职级集合按现有表注释先开放 P5–P8；如有其他职级，应扩展 `ProfileLevel` 并核对差旅政策。当前允许本人填写职级，与原有 Agent 档案写入能力一致。

证件类型对应关系：

| 编码 | 名称 |
| --- | --- |
| 0 | 身份证 |
| 1 | 护照 |
| 2 | 其他 |
| 3 | 回乡证 |
| 4 | 军官证 |
| 5 | 警官证 |
| 6 | 港澳通行证 |
| 7 | 台胞证 |
| 8 | 台湾通行证 |
| 9 | 外国人永久居留身份证 |

枚举字段不应由前端自由输入，使用 `/options` 返回的 `levels`、`genders`、`idTypes` 渲染下拉框。每个选项为 `{ "code": ..., "label": "中文名称" }`，证件类型的 `code` 为整数，其余为字符串；`editableFields` 列出可编辑和可清空字段。

## 保存与清空示例

首次创建：

```http
POST /user/profile
Content-Type: application/json

{
  "nickName": "张三",
  "baseCity": "南京",
  "namePinyin": "zhang san",
  "level": "P6",
  "gender": "M",
  "idType": 1
}
```

局部更新并清空字段：

```http
PUT /user/profile
Content-Type: application/json

{
  "email": "new@example.com",
  "clearFields": ["avatar", "idNumber", "phone"]
}
```

未提交或提交 `null` 的字段保持原值；空字符串不用于清空。`clearFields` 与提交非空新值的字段不得重叠，否则拒绝整次保存。两张表的修改处于同一事务，任意写入失败均回滚。个人中心与 Agent 写入共用账户行锁，档案读取直接查库，无额外档案缓存；昵称、头像写入后同步当前请求中的身份缓存。

## 错误行为

| HTTP 状态 | errorCode | 场景 |
| --- | --- | --- |
| 400 | INVALID_PARAMETER | JSON 格式、字段类型、枚举、长度或格式校验失败，包含未知字段 |
| 400 | INVALID_PROFILE | 空保存、同时修改和清空同一字段，或服务层校验失败 |
| 401 | AUTH_NOT_LOGIN | 未登录、凭据失效或账户不存在 |
| 403 | PASSWORD_CHANGE_REQUIRED | 当前账户必须先修改密码 |
| 404 | RESOURCE_NOT_FOUND | PUT 时尚未建立档案 |
| 409 | PROFILE_ALREADY_EXISTS | POST 时档案已经存在 |

无需变更现有数据库结构，`t_user.id` 的十进制字符串作为 `user_profile.user_id`。不执行迁移、初始化改表或账户删除。该功能不涉及动态配置表。
