## badcase
### L1层
#### 缺少排除词
```angular2html
问题：“我上周提交的出差申请现在到哪一步了？”
期望：`APPROVAL_QUERY` 审批进度查询
实际：`CREATE_TRIP_APPLICATION` 提交出差申请单

命中层级L1层
```
解决方案：原因是宽泛匹配“出差申请”会把查询已有申请进度误当成新建申请。正向正则需要识别“提交/创建新申请”这类动作，同时排除“上周提交”“到哪一步”等历史和进度表达。

#### 缺少正向正则关键词表达
```angular2html
问题： “帮我查一下去杭州的交通信息，最好给我高铁车次。”
期望：`PLAN_ITINERARY` 行程规划
实际：`TRAVEL_INFO_QUERY` 通用信息查询
L1 未命中
```
解决方案：原因是“交通信息”被宽泛规则识别成通用出行信息，而“查……高铁车次”这种“交通资源搜索”的正向正则表达没有被优先识别。因此 L1 提前短路

### L2层
- 出现问题: 一开始L2层写代码的时候, 没有注意设置一个分数过滤. 导致评测过程中路由到L2这个层级, 出现大量的错误识别.
- 问题排查: 经过代码排查发现, 没有设置一个分数过滤。导致检索到分数很低的相关的意图回来 0.1x分都有, 所以就导致意图识别在L2层大量错误
- 解决方案： 设置一个最低阈值分数为：0.85, 最终评测后发现badcase都解决了.
- 原因是什么： 因为L2层我们的一个设计目标是`宁愿不要命中, 也不要误命中`，太低的话就会导致大量的误命中，设置高一点就可以避免这个问题

### L3层
- 出现问题：L3层意图识别错误
- 解决方案：1. 换一个强模型 2.增加提示词规则约束 3.增加更多的few-show 4.cot思维链
- 现在存在的问题：当前L3层完全依赖大模型，因为大模型其实还是会有不确定性存在，这个点后续可以去做优化

优化方案:
1. L1层增加正向的正则关键词匹配, 还增加了排除词的匹配
2. 针对评测后的badcase补充更多的关键词-排除词匹配规则
3. L2层向量知识库阈值设置高一点：防止召回过低阈值的意图
4. L3层大模型兜底识别提示词优化：补充更多的few-show、cot思维链、意图分类路由表
