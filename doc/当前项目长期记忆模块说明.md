# 当前项目长期记忆模块说明

## 模块实现

当前长期记忆接入在 `ItineraryPlanningAgent`，使用 AgentScope 的 `LongTermMemory` 接口和 `Mem0LongTermMemory` 实现，后端为自建 Mem0（`http://localhost:8888`）。创建行程规划 Agent 时，从 `AgentRuntimeContext` 读取当前登录用户 ID，并作为 Mem0 的 `userId`，以用户维度隔离记忆。

Agent 同时配置了 `AutoContextMemory` 作为对话上下文记忆。它与长期记忆职责不同：前者服务于当前 Agent 对话上下文，后者跨对话存取用户记忆。

## 读写流程

1. 聊天流程创建运行时上下文并绑定当前用户 ID；创建行程规划 Agent 时读取该上下文。
2. `ItineraryPlanningAgent` 创建 Mem0 长期记忆实例，并配置自建服务地址、`SELF_HOSTED` 类型和用户 ID。
3. Builder 使用 `AGENT_CONTROL`，将长期记忆检索、记录工具注册给 Agent。
4. Agent 可根据任务需要调用检索工具获取该用户的已有记忆，也可调用记录工具将信息写入 Mem0；未调用工具时不会自动读写。

## 选择原因

行程规划只在部分任务中需要用户的长期偏好，且适合由 Agent 判断哪些信息值得检索或沉淀。`AGENT_CONTROL` 支持按需读写，避免 `STATIC_CONTROL` 每轮自动检索并在调用后记录短期 Memory 中的消息，减少无关记忆写入和不必要的后端调用。

相应取舍是读写依赖模型主动调用工具，存在漏检索或漏记录的可能。当前 `ItineraryPlanningAgentPrompt.md` 尚未明确记忆读写规则；若需要稳定的记忆行为，应补充何时检索、何种信息可记录及禁止记录的内容。
