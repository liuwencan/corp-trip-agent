# 途牛 CLI 鉴权说明

## 目的与范围

行程规划智能体调用途牛 CLI 时，需要使用当前登录用户自己的 TUNIU API Key，避免不同用户共用服务进程或开发机上的途牛凭证。本说明记录应用内 API Key 的保存、加密、读取、命令注入和安全校验流程。

当前应用内注入逻辑只作用于 `ItineraryPlanningAgent` 的 `execute_shell_command` 工具，并且只处理包含 `tuniu call` 的命令。它不改写 `tuniu auth`、`tuniu config`、`tuniu list`、`tuniu help` 等其他命令，也不适用于其他智能体。

## 两种凭证方式

途牛 CLI 支持 OAuth 和 `TUNIU_API_KEY`。项目 Skill 将 OAuth 作为优先方式，OAuth 不可用时才使用 API Key 兜底。CLI 的 OAuth source（如 `tuniu-cli`、`workbuddy`、`doubao`）和 OAuth 授权保存在 CLI 自己的用户配置目录中；项目的 API Key 则按应用登录用户保存在数据库中，两者是不同的凭证来源。

本项目的 Hook 为每次途牛业务调用从当前应用用户记录读取 API Key，并仅将它注入该次 Shell 子进程的环境变量。是否实际走 API Key 鉴权仍遵循途牛 CLI 自身的鉴权优先级；如 CLI 当前 source 已有有效 OAuth 授权，CLI 可能优先使用 OAuth。需要验证 API Key 路径时，应在隔离的测试环境确认 CLI 的实际鉴权行为，不要借用其他用户的 OAuth 状态。

## API Key 配置与存储

### 应用加密密钥

应用通过 `corp.trip.api-key-encryption-key` 读取用于加密用户 API Key 的主密钥。可在本机未提交的 `application-local.yml` 或运行环境变量中配置：

```yaml
corp:
  trip:
    api-key-encryption-key: "<随机生成并妥善保管的高熵密钥>"
```

Spring 环境变量形式为 `CORP_TRIP_API_KEY_ENCRYPTION_KEY`。所有需要读取这些密文的应用实例必须配置同一个密钥。密钥不得提交到 Git、写入日志或发送给用户。更换或丢失密钥会使已有密文无法解密；轮换前必须制定重新加密已有记录的迁移方案。

`AesUtil` 使用 AES-GCM：每次加密生成新的随机 IV，密文以 Base64 保存，解密时校验认证标签。AES 密钥由配置值经 SHA-256 派生为 256 位密钥。该主密钥与用户 TUNIU API Key 是两种不同的凭证。

### 用户 API Key

`save_provider_api_key` 接收用户明确提供的密钥，并使用当前会话的用户 ID 保存。`ProviderApiKeyService` 在写库前调用 `AesUtil.encrypt`；新增和更新最终写入 `user_provider_api_key.api_key_ciphertext`，数据库不保存 API Key 明文。表以 `(user_id, provider_code)` 唯一约束隔离每个用户的平台凭证，`status` 为 `ACTIVE` 时才可用于调用。

状态查询只返回平台与配置状态，不返回明文或密文。途牛调用时，`getActiveApiKey(userId, "TUNIU")` 只查询当前用户的 ACTIVE 记录，再用同一个 `AesUtil` 解密供后端临时使用。

新环境初始化可参考 `sql/init.sql`；已存在环境应先执行 `sql/migration/V20261101__user_provider_api_key.sql`。迁移前确认 `t_user` 表和 `t_user.id` 已存在。该迁移只新增凭证表，不会把明文凭证从旧位置自动导入。

## 命令改写流程

1. `TuniuApiKeyShellHook` 以优先级 `10` 运行，早于优先级 `100` 的 `ProgressNotificationHook`。
2. Hook 只接受名称为 `ItineraryPlanningAgent` 的智能体及 `execute_shell_command` 工具，并识别 `tuniu call`。
3. Hook 从本次 Agent 调用的 Reactor 上下文读取用户 ID，按用户 ID 查询 ACTIVE 的 `TUNIU` Key 并解密。上下文无用户、用户 ID 无效或没有启用的 Key 时，调用失败关闭，不执行途牛命令。
4. Hook 将凭证加入命令环境，并替换 `ToolUseBlock` 的 `command` 参数。Windows 下的格式为：

```cmd
set "TUNIU_API_KEY=<当前用户的解密后密钥>" && tuniu call hotel tuniuHotelSearch --source tuniu-cli -a "{\"cityName\":\"广州\",\"checkIn\":\"2026-12-01\",\"checkOut\":\"2026-12-03\"}"
```

双引号是 CMD 的 `set` 赋值语法，用于防止分隔符前的空格进入变量值。AgentScope 1.0.12 在 Windows 使用 `cmd.exe /c`，所以不能使用 PowerShell 的 `$env:...` 赋值语法。

Linux/macOS 下使用 POSIX Shell 格式：

```bash
export TUNIU_API_KEY='<当前用户的解密后密钥>'; tuniu call hotel tuniuHotelSearch --source tuniu-cli -a '{"cityName":"广州","checkIn":"2026-12-01","checkOut":"2026-12-03"}'
```

5. `TuniuShellCommandValidator` 只对上述受限的 API Key 前缀加单条 `tuniu call` 命令剥离前缀，并将实际途牛命令交给 AgentScope 对应操作系统的默认校验器。其他包含 `&&`、`|`、换行等多个命令的输入仍会被拒绝；带 API Key 前缀的其他可执行程序也会被拒绝。
6. 进度通知会在向前端发送工具参数前隐藏注入的 `TUNIU_API_KEY`。Hook 审计日志记录用户 ID、改写前命令和改写后命令；改写后命令中的密钥显示为 `[已隐藏]`。

## 安全约束

- 不要在对话、命令参数、Skill 文档或日志中复述真实 API Key。API Key 只能通过明确的用户意图保存，并只存在于数据库密文和调用时的短暂内存/子进程环境中。
- 用户命令若自行设置 `TUNIU_API_KEY`，Hook 会拒绝执行，避免覆盖当前用户凭证或绕过用户隔离。
- Windows CMD 注入会拒绝含换行、`%`、`&`、`|`、`<`、`>`、`^`、双引号等命令特殊字符的 Key，避免改变命令结构。遇到该情况应调整为不经过 Shell 拼接的进程环境变量传递方案，不要放宽为任意命令执行。
- 审计日志中的原始命令可能含搜索条件、订单参数或个人信息。日志应限制访问和保留时间；不得把完整手机号、证件号、OAuth Token 或 API Key 写入日志。
- `TUNIU_API_KEY` 是单个子进程环境变量，不会修改应用全局环境或其他并发用户的环境变量。
- API Key 配置检查成功仅表示应用有可解密的凭证，不代表 CLI 已选用该凭证，也不代表途牛业务调用成功。业务结果必须以 CLI 返回为准。

## 常见问题排查

| 现象 | 可能原因 | 检查方式 |
|---|---|---|
| `corp.trip.api-key-encryption-key is not configured` | 应用加密主密钥缺失 | 检查 `CORP_TRIP_API_KEY_ENCRYPTION_KEY` 或本地配置，并重启应用 |
| 当前用户未配置可用的 TUNIU API Key | 没有保存、状态不是 ACTIVE，或 Agent 上下文没有用户 ID | 使用 `query_provider_api_key_status` 检查当前用户，不要查询或借用其他用户凭证 |
| `SecurityError: Command contains multiple command separators` | Hook 前缀未被 `TuniuShellCommandValidator` 识别，或自定义命令包含额外分隔符 | 确认使用当前行程规划 Agent 的 Shell 工具、前缀格式与单条 `tuniu call`；检查 Agent 是否接入自定义 validator |
| 认证失败（途牛 CLI 退出码 104、108、109、110、111、112） | OAuth source 未授权、API Key 无效/缺失，或 CLI 优先选择了另一个 OAuth source | 按 `src/main/resources/skills/tuniu-cli/SKILL.md` 的 source 规则检查 `tuniu auth use --show`、`tuniu auth status`；API Key 失败时由用户更新自己的 Key |
| 工具或参数错误（退出码 102、103） | server/tool 名称或参数不符合当前 CLI Schema | 先读取 `src/main/resources/skills/tuniu-cli/references/<server>.md`，必要时执行 `tuniu list`、`tuniu schema` 或 `tuniu help` |
