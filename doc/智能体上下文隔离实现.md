# 智能体上下文隔离实现

## 目标

在同一业务会话中，主智能体和不同子智能体可以分别保留自己的多轮对话状态；不同业务会话之间也不能读取或覆盖彼此的智能体状态。实现依赖 AgentScope 的 `Session` 持久化能力，并由 `PersistSessionHook` 在智能体调用前后加载和保存状态。

这里的“上下文隔离”是运行时会话状态的持久化隔离。它不代表用户权限校验，也不替代业务会话及消息历史表。

## 关键组成

- `PersistSessionHook`：监听智能体生命周期事件，按当前会话加载或保存 Agent 状态。
- `AgentRuntimeContext`：携带当前调用的用户 ID 和业务会话 ID。Agent 创建时由 `AgentRuntimeContextHolder` 取得，并注册到 `ToolExecutionContext`。
- `CorpTripSessionKey`：以业务会话 ID 和智能体名称共同生成 AgentScope 的持久化标识。
- AgentScope `Session`：由 `CorpTripAgentHookConfig` 注入到 Hook，负责 Agent 状态的持久化存取。
- Prototype Agent：主智能体和通用信息子智能体按会话创建，使 Agent 实例和其内存不由不同请求共享。

## 隔离键

`CorpTripSessionKey.toIdentifier()` 使用以下格式生成存储标识：

```text
{sessionId}_{agentName}
```

例如，会话 `108` 中的主智能体和通用信息子智能体分别使用：

```text
108_MasterAgent
108_GeneralInfoAgent
```

因此，两个维度共同决定一份持久化状态：同一会话内不同智能体分开存储；同一智能体在不同会话中也分开存储。当前隔离依赖智能体名称稳定且唯一；重命名 Agent 会切换到新标识，旧标识对应的状态不会被该名称自动加载。

## 调用流程

1. 请求处理流程建立当前调用的 `AgentRuntimeContext`，并通过 `AgentRuntimeContextHolder` 供 Prototype Agent 创建过程读取。
2. 创建主智能体时，将运行时上下文注册进 `ToolExecutionContext`；主智能体调用的 `GeneralInfoAgent` 也按 Prototype 方式创建并注册上下文。两个 Agent 均配置 `PersistSessionHook`。
3. Hook 处理事件时跳过 `ReasoningChunkEvent`，避免对推理流中的每个片段重复执行持久化操作。
4. 对 `PreCallEvent`，Hook 根据当前 `sessionId` 和事件所属 Agent 名称生成 `CorpTripSessionKey`，调用 `agent.loadIfExists(session, sessionKey)`，恢复该 Agent 上次保存的状态。
5. 对其他未被跳过的 Hook 事件，Hook 调用 `agent.saveTo(session, sessionKey)`，将当前 Agent 状态写入对应 Session。
6. 下一轮相同业务会话、相同 Agent 名称的调用会使用相同标识恢复状态；其他会话或其他 Agent 使用不同标识。

## 隔离边界

- **会话内 Agent 隔离**：隔离键包含 `agentName`，主 Agent 和子 Agent 不共用同一份持久化状态。
- **会话间隔离**：隔离键包含 `sessionId`，同一 Agent 在不同业务会话中分开存储。
- **并发请求隔离**：Prototype Agent 避免跨请求共享同一个 Agent 实例；Hook 本身共享注入的 Session，但每次读写均使用当前事件对应的隔离键。
- **非目标范围**：`userId` 当前不参与 SessionKey 生成。用户与会话的归属应由业务会话接口及服务层校验保证，不能仅凭此 Hook 实现数据授权隔离。

## 当前实现注意点

1. Hook 通过 Reactor Context 获取 `agentRuntimeContext`。源码注释提到缺少 Reactor Context 时回退到 Agent 创建时上下文，但当前实现没有完成该回退；如果 Reactor Context 中没有该对象，后续读取 `runtimeContext.getSessionId()` 会触发空指针。运行链路必须保证传播该上下文，或在代码中补齐空值保护及可靠回退。
2. 当 `sessionId` 为 `null` 时，Hook 会直接返回事件，不执行加载或保存。空字符串目前不会被视为缺失值，因此调用方应提供有效、稳定的会话 ID。
3. 当前保存分支涵盖除 `ReasoningChunkEvent` 和 `PreCallEvent` 以外的事件，并非只在某一种明确的“调用结束”事件保存。若 AgentScope 事件类型或生命周期语义变化，应核实保存时机及写入频率。
4. `CorpTripSessionKey` 用下划线拼接两个字段，没有转义机制。若字段允许包含下划线，需保证组合不会产生标识冲突，或改为无歧义编码。
5. 持久化可恢复 AgentScope 运行时状态，但不等同于业务消息表中的对话记录；两者各自承担运行时恢复与业务历史展示职责。
